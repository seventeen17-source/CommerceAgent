## 遇到的问题

- **计划里的 Spring Boot 3.5.x 已无法由官方 Initializr 生成**：`GET start.spring.io/starter.zip?bootVersion=3.5.11` 返回 HTTP 400，服务端信息为 `"Invalid Spring Boot version '3.5.11', Spring Boot compatibility range is >=4.0.0"`。计划要求的版本与「必须使用官方生成器」两条约束互相冲突。
- **Initializr 元数据里的版本 id 不能直接当作 Maven 坐标**：元数据列出的 id 是 `4.1.1.RELEASE`，照传后 Initializr 返回 200 并把 `4.1.1.RELEASE` 原样写进 `pom.xml`；但该坐标在 Maven Central 为 404（`4.1.1` 才是 200）。改用 `bootVersion=4.1.1` 后正常。
- **Testcontainers 启动失败的根因是 Docker 代理端口配错**：Docker Desktop 走本地代理，端口写成 7897，而实际代理监听 7892，导致容器相关连接失败；改为 7892 后恢复正常。
- **环境变量不会热更新到已运行的进程**：JDK 21 安装并写入 Machine 级 `JAVA_HOME` 后，先前已启动的 shell 仍读不到（`JAVA_HOME` 为空、`java` 不在 PATH）。需要新开进程，或显式使用绝对路径调用。
- **本会话 shell 无法访问 Docker 命名管道**（`npipe:////./pipe/dockerDesktopLinuxEngine` 权限拒绝），因此无法在会话内复跑 Testcontainers 测试；改为交叉核验 `target/surefire-reports/` 产物来确认测试结果。

## 今天学到

- **生成器返回 200 ≠ 生成的工程能构建**：必须回到真实制品仓库（Maven Central）核对坐标是否存在，否则会在第一次 `mvnw` 时炸掉。
- **Maven Wrapper 与 JDK 是两件事**：wrapper 保证 Maven 版本一致（本工程锁定 Maven 3.9.16），但它本身需要一个 JVM 才能启动；没有 JDK 时失败发生在「启动 Maven」这一步，与 `pom.xml` 里的 `<java.version>` 无关。
- **`<java.version>21</java.version>` 只是一句声明**：它由 Boot parent 里的 `maven-compiler-plugin` 读取并转成 `--release 21`，不代表机器上真的装了 JDK 21。
- **scope 是 classpath 的划分**：`runtime` scope 的依赖（`org.postgresql:postgresql`）不进编译 classpath，主代码 `import` 它会直接编译失败——这是防止数据库实现泄漏进业务代码的护栏。
- **Spring Initializr 产出的是工程骨架**，不是业务代码；`BUILD SUCCESS` 只证明骨架可构建、容器可启动，不证明任何业务能力。
- **测试通过 ≠ 应用能独立启动（本轮已实测）**：`mvnw.cmd test` 里 DataSource 由 `TestcontainersConfiguration` 的 `@ServiceConnection` 注入，而 `application.properties` 中仍只有 `spring.application.name`。直接执行 `mvnw.cmd -DskipTests spring-boot:run` 的实测结果为 `APPLICATION FAILED TO START — Failed to configure a DataSource: 'url' attribute is not specified and no embedded datasource could be configured`，失败链路为 `entityManagerFactory → flyway → dataSource(Hikari) → Failed to determine a suitable driver class`。生产启动路径的配置缺口留给 T005 / T007，此处不提前补。
- **`main` / `test` 两套源码根是构建语义**：`src/main/java` 进最终 jar，`src/test/java` 不进；放错位置会得到「编译通过、测试也过、运行 404」这类最难查的问题。
