## 本次学习检查点

- `@Version` 是乐观锁，解决“同一已有行的并发覆盖”；它不能阻止两个线程各自 INSERT 两条新退款记录。
- “同订单最多一笔活动退款”由数据库 partial unique index 最终保证；订单 `SELECT ... FOR UPDATE` 用于把同订单写路径串行化。
- 第一次 idempotency 检查与拿到订单锁之间，另一个请求可能已经提交，因此锁后二次检查必须保留。
- write timeout 代表 **outcome unknown**，不是失败；Idempotency-Key 防重复副作用，verify-after-write 用权威读面确认“上一次到底提交没有”。
