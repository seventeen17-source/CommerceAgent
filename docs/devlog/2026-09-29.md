### 遇到的问题

- **护栏第一版是"零容忍"，把三处合法历史代码判成违规**。`model_copy(update=...)` 白名单最初写成"一处都不许有"，结果 `store.py`（写路径）、`checkpoint.py`（读路径）、`dev_t031.py`（dev harness）全部命中。逐个查完才确认：前两处只把"行上更新的 5 个共享列"盖回 payload，方向是刻意设计的；第三处是 dev-only。**正确顺序是先判断存量是不是真漏洞，再决定规则边界**——否则我会为自己的新规则去改生产代码。最终改为显式白名单 + "白名单过期也失败"的双向断言。
- **`transition()` 是同一个不变量的第二条写路径**，且只有它没设闸。这类"两条路径一个不变量"是典型的 fail-open：`advance()` 拦得住，SQL 那条拦不住。
- **`model_copy(update=...)` 跳过校验是实测事实**，不是文档推测；langgraph 1.2.11 的节点更新也会把状态合并成普通 dict 而不重新校验模型（over-budget 与 extra 字段都被接受）。这两条一起决定了：图状态必须是 `TypedDict` 包一层，且每次变更都走 `advance()`。
- **我自己的操作失误**：用 PowerShell `Set-Content -NoNewline` 做文本替换，把 `graph.py` 整个压成一行。因为该文件**尚未提交**，git 恢复不了，只能整份重写（内容没丢，但白费一轮门禁）。**教训：源码改动只用编辑器工具，不要用 shell 做文本替换。**
- **环境故障**：工作区目录的文件权限缺少"取得所有权"，导致命令随机以 `SetNamedSecurityInfoW failed (Win32 5)` 失败。用 DSH 的文件权限诊断脚本修复后验证通过（1286 个对象已扫描，未改动文件内容与所有者，未移除任何授权项）。但 `.ruff_cache` / `.mypy_cache` / `.pytest_cache` 三个缓存目录仍有不继承父级的权限项且拒绝删除 → 门禁改用等价命令：`ruff check --no-cache`、`ruff format --check --no-cache`、`mypy app --cache-dir=<TEMP>`，pytest 本来就用 `-p no:cacheprovider`。

### 关键决策

- **持久化自管，不用 LangGraph 自带 checkpointer**（`compile(checkpointer=None)`）。实测确认框架的 checkpointer 确实按节点落盘，所以这是取舍不是能力限制：选它会产生第二份状态真相，而 T017 的 `RunStore` 已经有验收过的 row lock + version CAS + owner 谓词 + retention。代价是暂时没有框架原生 `interrupt()`，HITL 留 T049 决策。
- **`GraphState` = 1 个载荷通道 + 3 个控制面通道**（`decision` / `understood` / `resolution`）。后三者是"本次 invocation 的中间产物"，`resume` 时重新推导，**绝不持久化**——持久化它等于把"模型的解释"和"Java 的事实"并排放，后来的人分不清哪个是证据。
- **未识别的 intent 走 `WAITING_USER` 而不是猜**：没有目标就无从判断哪个 capability 合适。
- **evidence guard 拒绝的是那次工具调用，不是整条 run**：证据少一点仍交给 Java 判资格，它才是权威；而"没有 proposal"才拒绝。
- **`SAFE_STOP` 必须带机器可读 reason code**，由 `TerminalDecision` 的构造器保证（`SAFE_STOP` 无 reason 在类型上构造不出来）。`verification = UNKNOWN` 落 `SAFE_STOP` 而非 `COMPLETED`，因为 T017 的 retention 对 `SAFE_STOP` 保留 trace 90 天——钱可能已经动了又说不清时，trace 是唯一能对账的东西。

