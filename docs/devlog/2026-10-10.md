## T055 最小 Approval Center — Live Gate

### 实现与边界
- 新增 `Approval Center · 人工审批中心`，仅使用 APPROVER Token；工作台从 Java `GET /approvals?status=PENDING` 读取权威待审批记录，展示 order/action/amount/risk reason、Approval/Run ID 与时效。
- Approve / Deny 均要求二次确认；决策后不做 optimistic update。若返回 409 或结果未知，页面要求重新读取 Java Authority 后再操作，避免 blind retry。

### Live Eval 真实结果
```text
[pass] us4-high-risk-waits-for-approval: business state matches the case
[pass] us4-denied-cannot-resume: business state matches the case
[pass] us4-cross-bound-approval-id: business state matches the case
[pass] us4-attempted-self-approval: business state matches the case
{"pass": 4}
```
- high-risk：Run 停在 `WAITING_APPROVAL`，存在且仅存在 1 条 PENDING approval，0 refund/return write。
- denied：APPROVER 把权威 approval 置 DENIED 后，customer Resume 返回 `409 APPROVAL_DENIED`，0 write。
- cross-bound：为同一订单但不同 run 创建并批准另一条 approval，把其 id 提交给原 run Resume，返回 `409 APPROVAL_REFERENCE_MISMATCH`；原 run 的 PENDING 引用不能被替换，0 write。
- self-approval：customer token 直接调用 decision APPROVE，Java 返回 `403 ACCESS_DENIED`，approval 仍 PENDING，0 write。
