## 遇到的问题

- **推送被本机代理阻塞了两次**：`127.0.0.1:7892` 关着时 `git push` 直接失败，单次绕过代理直连也是 `Connection was reset` —— 这台机器的出网真的依赖它。处理方式：把工作全部提交在本地分支上、在文档里如实写成"推送被代理阻塞，合并前需确认远端状态"，代理回来后再推。**没有为了"看起来完成"而写成已推送**。
- 沙箱的文件策略在会话中途从 workspace-write 变到 danger-full-access 又变回来，导致同一串 git 命令在两种模式下结果不同；结论：git 写操作（`.git`）与凭据助手的命名管道都需要提权，命令里要**逐步检查退出码**，不能串成一条不管失败的脚本。

### 两条 B-class 默认（写死，除非反对）

- 候选**上限 5 笔、按 `createdAt` 倒序**；
- **上限不是安全边界**：安全边界始终是"客户回答前一个字节都不写"；界面上必须如实说明"只显示最近 5 笔，都不是请直接说明"。

### 要钉住的 8 条边界用例

1. 命中恰好 1 张 → 仍须经 Java `get_order` **确认 ownership** 才算解析（线索不是身份）；
2. 命中 ≥2 张 → 提问，候选 = 命中的那些（封顶 + 最近优先）；
3. 命中 0 张 → 换更宽的问法，**绝不写**；
4. 无线索（"上次买的那个"）→ 候选 = 全部（封顶），提问；
5. 线索是泛词（"东西"/"商品"/空串）→ 视作无线索，**不能"匹配所有"**；
6. 本人订单 ≤1 张 → 无需澄清（保持现状）；
7. 两张订单商品摘要相同 → US3 主场景 → 提问；
8. 某张订单 `productSummary` 为空 → 该张**不算命中**（不能因字段缺就当作匹配）。
