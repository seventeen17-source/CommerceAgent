# UI-1.0 七页 UX 与组件规格

本文件所有尺寸使用 design-system.md。实现不自动代表视觉获得用户批准。每页先用固定场景截图验证，再接Live同一组件。

## P01 工作总览 Dashboard

目的/用户：企业人员与比赛评审30秒内看懂正在执行的任务及人工边界。主操作：选择Run进入Workspace。

布局：头部112px；生命周期说明88px；四指标104px一排gap16；主体minmax(0,2fr)/minmax(300px,1fr)。1600时内容区1328px，左右约875/437含间距；自然向下延展。

模块：产品标题与数据范围；Request→Evidence→Decision→Controlled Action→Verification说明条；主数字用同一口径的**绝对条数**「任务N → 未越界免人工完成并核验A / 人工介入H（越界等待审批或转人工）/ 自动恢复并权威确认S」，比率（A/T）只作副标并标注分母；近期Run卡列表；Attention Required。四张等权卡片不允许让三个例外指标（人工介入、恢复、Attention）压过“默认自主”这一个事实。

Run卡最小136px：首行ID+状态，第二行任务摘要，第三行真实阶段轨迹，右侧“查看执行”。Handoff可跳过；Recovered仅为有恢复证据的附加标签，不能替代Run状态。Attention项显示暂停原因、审批引用/工单引用、来源时间，只导航不直接审批。

筛选：今日/7日、状态；服务端分页20条，加载更多保留滚动。切筛选清空旧请求结果；空态“此范围内暂无任务”；统计失败与列表失败独立呈现。顶部系统健康只有探测结果时显示，否则“状态未获取”。有限回放不能叫实时推送，列表标题为“近期Agent Runs”，标最后刷新时间。

按钮：Run→P03，审批→P05指定approvalId，恢复→P06指定runId，指标→P07同筛选。无记录不放假样例；Demo使用明确隔离样例。

验收：数字有口径/范围/分母；权限内查询；未经过节点不标完成；所有深链接指向同一Run。示例值（326/91.4%/21/7）不得作为事实渲染：Demo 必须带 Demo 标识，Live 无样本用“— / 无样本”；“免人工完成”不得写成“自动审批”。

## P02 Customer Portal

目的/用户：客户描述问题、选择本人订单、看业务进度、按需澄清。避免内部技术语言。

布局：页面标题88px；提交态左右5:7，左表单、右“处理方式”简述；提交后左只读请求摘要和订单、右真实进度/结果。移动端表单→订单→提交；提交后结果在首屏。与customer.png同色彩/卡片，不复刻同时可提交与已运行的矛盾状态。

表单：售后问题textarea最小140px，label始终可见；trim后1–4000字符；空白提交就地报错并focus；Ctrl+Enter提交，普通Enter换行。示例诉求只填输入，不自动发送。订单可选，不强制绕过自然语言澄清。

选单：本人订单摘要卡，金额只在详情成功后展示；单选不自动提交。提交请求体当前只有message；选中订单以固定文本“关联订单：{orderId}\n问题：{原文}”加入message，不声称获得结构化强绑定。最终仍以服务端解析及归属结果为准；若需强绑定参数，必须先变更契约。

状态：
- Draft：可编辑、按钮“提交售后请求”。
- Submitting：锁提交，保留原文，提示“正在处理”；不伪造Run编号/节点/百分比。
- WAITING_USER：显示服务端澄清原因；候选卡只来自本轮candidateOrderIds；“确认并继续”调用同Run input，成功后禁用旧卡。无候选显示补充文字输入。
- WAITING_APPROVAL：显示“等待人工审核”；可查审批状态，权威APPROVED后“继续处理”调用同Run resume。审批决定未通过时按钮不放行。
- Verified refund/return：分别展示申请号/业务状态/确认依据；退货不得用退款文案。
- ESCALATED：有工单确认才显示编号；否则“转人工结果待确认”。
- SAFE_STOP/FAILED/UNKNOWN：明确是否已知写入，不说“请重新提交试试”。未知ID显示“无法确认本次请求结果，请勿重复提交”；不自动POST。

按钮：提交→create；澄清→input；查询→GET；继续→resume；详情→P04。无取消/保存草稿/催单按钮。刷新后重新认证并读取已知Run；原文未获服务端提供时诚实缺省。

验收：无图布局完整；双击只有一次提交；切身份迟到响应不回填；审核等待无再次提交；真实节点不可得时只显示当前业务状态，不机械打四个绿勾。

## P03 Agent Workspace（结构冻结）

目的：监管单次Run的证据、动作、权限与核验。视觉必须对照workspace.png。

≥1440主内容三栏：队列240px，Trace minmax(420px,1fr)，Context360px，gap16；1600时Trace496px。1280三栏200/minmax(360,1fr)/280，gap12；<1280按design-system抽屉折叠。顶部RunHeader最小112px；底部Verification最小88px。长内容允许纵向增加，不强塞一屏。

头部：Agent Run · 任务类型；真实runId、status、订单、金额；负责人无来源显示“未提供”；请求原文仅授权摘要。状态徽标靠标题；技术健康放最右且仅真实探测。头部含**边界账**（同一组件两态）：规则码+版本、可退金额、审批阈值（仅权威提供时）、判定“未越界→直接执行”或“金额≥阈值→越界，已暂停等待审批”；阈值无来源只写“业务规则要求人工审批”。

Trace七个展示分组：Intent Understanding / Order Resolution / Evidence Collection / Decision Making / Human-in-the-loop / Tool Execution / Verification。它们是展示分组，不强制Agent走固定七步。每组节点名称、状态、Tool、输入摘要、输出、来源；同组多次实际事件按时间追加，未经过标“不适用”或“未执行”，不可推断完成。澄清、退货、安全停止和转人工为实际分支行，不能套退款模板。

默认选中：**默认基准是未越界路径**（节点1–4完成、HITL 组标“不适用”、写入执行、底部VERIFIED_SUCCESS）；越界等待是**对照**基准，不是默认。终态默认Verification或停止原因；切Run重置选中和旧上下文。点击节点→右栏相应快照，URL记node ID；展开查看结构化摘要、错误码、时间。无Tool写“不适用”，不杜撰调用。时间无来源“未记录”。

Context固定Evidence→Rule→Decision→Action Boundary→Verification：事实区显示订单/物流/归属来源；规则码/版本及可提供阈值；Agent提议和Java资格结论分开；审批要求来自Java；执行边界分别显示允许动作、尚缺条件；验证说明确认方式。

HITL高亮：风险原因、审批绑定、暂停资金动作、等待角色；批准前Tool状态“未执行/等待审批”。审批阈值不可得时写“业务规则要求人工审批”，禁止填300。

底部只展示本次Verification：NOT_RUN未开始、PENDING等待核验、UNKNOWN待确认、VERIFIED_FAILURE核验未通过、VERIFIED_SUCCESS及匹配资源。回收时说明原因。退款创建不等于到账，工单响应确认不等于读回核验。

操作：查看审批→P05；案件→P04；异常/工单上下文→P06；复制ID本地。没有生产能力不显示“强制执行/重新退款/解除安全停止”。审批按钮不放在Context里。

验收：三栏主次/字号/位置对照；**未越界与越界两态使用同一组件，视觉差异只来自事实（阈值比对结果）**；反事实分支可见；无模型隐藏推理；来源可点；UNKNOWN不绿；未实际授权不能读取他人Run。

## P04 Case Detail

目的：展示业务对象与结果，过程回P03。客户只看本人安全投影，企业必须经运营读取授权。

布局：标题+状态+“查看执行过程”；主体三列27%/43%/30%，gap16；窄屏请求→订单证据→结果。卡片最小宽220px。

左：用户问题原文/合法摘要、提交时间、Run关联；无来源不推测。中：无图订单（ID、items摘要、金额币种、订单状态）、物流快照（状态/签收/最近有效时间/停滞小时）、规则引用；区分“本次执行依据”和“当前业务查询”，各有时间。右：资格、审批状态、实际动作、退款/退货/工单号、验证状态、确认方式；未完成显示待处理，不填预期编号。

交互：展开商品列表；复制编号；查看证据来源drawer；刷新当前业务状态只读，不覆盖当次历史证据；“查看执行过程”回同Run同角色。禁改金额/资格，禁新增退款按钮。

状态：订单查询失败保留Run结果；部分缺数据分区降级；取消访问不泄露对象；存在退款与退货多个对象时逐项列出并按服务端引用关联，不取第一行当本次结果。

验收：同Run跨页ID一致；清楚区分资格/审批/申请创建/核验；不重画完整Trace。

## P05 Approval Center

目的：批准明确绑定的业务提议，突出Agent已暂停敏感写入。用户：服务端APPROVER。

布局：头部88；左320px待办列表，右minmax(0,1fr)决策详情。详情顶部amber BoundaryCallout；下方证据与绑定两列；底部操作区，长页内sticky但不遮正文。

列表：PENDING/APPROVED/DENIED/EXPIRED筛选，显示ID/动作/金额可空/申请时间。详情：runId、orderId、actionType、amount、ruleCode、riskReason、expiresAt、decision。纯退货金额为空显示“不涉及本次退款金额”，不是0。

Agent建议标“拟执行动作”；安全说明“资金动作等待授权”。物流240h只有授权的审批证据摘要提供才显示；不能用APPROVER token偷调客户订单接口或切客户token。

批准/拒绝：弹窗复述订单、动作、金额、审批引用；默认取消；确认一次POST decision。当前契约只有decision，不收集不能保存的审批意见。成功只写“审批已批准，等待原任务继续”，不标退款完成。409/过期刷新；响应丢失锁按钮并查询全部审批状态定位ID，不能只查PENDING后把消失当成功。状态未知不允许再决策。

已有决定/过期/无权时操作区只读。审批通过仍由客户原Run resume→服务端重读绑定/资格→执行，审批台不代客户发退款请求。

验收：拒绝/过期/错绑定零越权写；双击/并发审批冲突正确；审批后进入Workspace仍需合法运营读取授权。

## P06 Recovery Center

目的：展示失败证据、恢复动作和权威结果。默认只读审阅，不发明人工恢复终态Run能力。

布局：左280px异常列表；中主要区域Failure Event / Recovery Action / Verification Result三段；右320px业务副作用与来源（小屏drawer）。顶部显示Run状态与结果未知提示。

列表：错误类型、发生时间、当前状态、recovered附加标记。详情呈现真实序列：Tool超时→写入结果未知→权威查询→已找到原资源→核验成功。只有实际事件存在时才出现每一段；自动恢复过程不得虚构曾进入终态SAFE_STOP。

三种分支：A已存在资源→确认原对象、不再次写；B权威确认安全→同逻辑请求有限重试（只能展示真实执行）；C仍未知→停止继续写、等待人工核查。重试次数/是否同逻辑请求由安全摘要提供，不展示原始幂等键。

操作：“重新读取记录”只GET；“查看业务结果”P04；“查看完整执行”P03；有工单时打开工单摘要。不存在人工恢复命令时不显示“恢复任务/重试退款”；接管入口不声称工单已被某人接单。

验收：未知不是失败或零写；Recovered需要恢复证据+权威确认；SAFE_STOP终态不能被UI resume；没有工单不能写已转人工。

## P07 Analytics

目的：用可追溯运行统计说明项目价值，非BI。企业只读。

布局：头部时间范围/数据范围/时区；四指标卡104px；下方左2/3失败类型水平条形列表，右1/3指标定义；底部最多10条可钻取样本。最多一个图表，禁止虚构成本节省。

范围：today/7d/30d；时区Asia/Shanghai；半开区间[start,end)；按Run createdAt选同一批cohort，统计asOf时刻状态，distinct runId。任务数=N；已终止数=T；验证成功数=V；**免人工完成并核验成功数=A**（无人工介入事件且核验成功；其中 A1=未越界自主执行并核验成功（`eligibility.approvalRequired=false` 且写入成功），A2=无需资金动作的自主完成；两个小类必须能钻取到证据，否则 A 只能按字面解释为“无人工介入的核验成功”）；人工介入数=H（曾进入审批或实际转人工）；发生恢复尝试数=R；恢复后权威确认数=S。越界等待审批不计入 A，也不计入失败。

指标：运行数N；任务验证成功率V/T；人工介入率H/N；恢复成功率S/R；Dashboard 免人工完成率A/T（P01 主数字用绝对条数，比率仅作副标并标分母）。分母0显示“— / 无样本”，不是0%。名称/分母/时间范围在tooltip和来源抽屉可读；仍运行数量单列说明不计T。业务拒绝与安全停止不算业务验证成功，也不能当unsafe failure。禁用“自动审批”“自动批准”：越界的正确说法是“已暂停等待审批”，未越界的正确说法是“未越界直接执行”。

失败类型按真实错误事件聚合，每Run每类型计一次；多个类型可重叠并注明，不能拿总和作Run数量。未识别code归“其他”，保留授权样本可查。运行统计和离线Eval报告分别标数据集，不能互相冒充。

操作：卡/类型→授权Run列表→P03；范围变更时全部统计同一请求版本；加载/失败不沿用旧值当当前；无报告正确空态。

验收：每个数字可定位来源、查询范围和实际Run；少量演示不能称全项目性能；Demo数字不能出现在Live或README成果。
