## 为什么值得补

T016 已经通过 CommerceClient 测试间接覆盖 token 转发，但如果未来有人把 `AuthContext` 改成：

```python
AuthContext(token=..., user_id="customer-001", role="CUSTOMER")
```

就会把“凭据用于证明身份”悄悄退化成“调用方直接声明身份”。新增测试把这个架构边界钉死。

## 面试压缩

> 我把认证上下文设计成只携带 credential 的 `AuthContext`，而不是身份对象：Python 只能转发 Bearer token，真正的 userId/role 必须由 Java 根据已验证 JWT 和当前用户记录返回。这样“调用方伪造身份”在类型层面就无法表达；同时用 `SecretStr` 和 header-safe validator 防止 token 进入日志或通过 CR/LF 注入 HTTP header。
